# 云上农管家 - 农产品价格预测全流程设计方案 (专业级)

## 1. 架构总览 (Architecture Overview)

本项目旨在构建一个工业级、高可用的农作物价格预测系统。系统覆盖从**权威数据源采集**、**数据清洗与资产化**、**特征工程**、**多模型融合预测**到**前端业务展示与预警**的完整生命周期（Full Lifecycle）。

核心链路设计为五层架构：
1. **数据采集层 (Data Collection)**：对接权威信源，实现多源异构数据的自动化获取。
2. **数据治理层 (Data Governance)**：完成数据的清洗、对齐、落库，构建标准化数据仓库。
3. **算法引擎层 (Algorithm Engine)**：基于时序数据和外部特征，利用分档混合模型输出带置信区间的预测结果。
4. **服务部署层 (Service Deployment)**：实现离线训练与在线推理分离，并提供 Node.js 层的优雅降级策略。
5. **业务展示层 (Business Loop)**：在前端渲染预测曲线与置信带，结合大模型输出定性分析报告，辅助农户决策。

---

## 2. 权威数据获取与治理平台 (Data Acquisition & Governance)

这是预测系统的基石。没有准确、权威、连续的数据，任何预测模型都无效。

### 2.1 权威数据源矩阵 (S/A/B/C 分级)
*   **S级 (核心官方数据)**：农业农村部信息中心（全国农产品批发市场价格信息系统）、国家统计局、发改委农产品价格监测。此类数据作为**基准真值 (Ground Truth)**。
*   **A级 (大型集散地数据)**：全国性骨干农产品批发市场（如北京新发地、寿光蔬菜指数、武汉白沙洲）。提供高频、细粒度的区域指导价。
*   **B级 (商业数据接口)**：Wind、万得、布瑞克农业数据等商业 API（作为补充校验）。
*   **C级 (互联网非结构化数据)**：农业资讯网站、行业公众号等（用于 RAG 大模型提取定性情绪特征）。

### 2.2 数据采集链路设计
*   **采集方式**：
    *   **API 轮询**：针对提供标准 API 的商业或政务平台，使用 Node.js `node-cron` 定时任务每日凌晨拉取。
    *   **RPA/定向爬虫**：针对只提供网页展示的政务公开数据，通过 Python (Scrapy/Playwright) 建立定时抓取任务，伪装并遵守 `robots.txt` 规范。
*   **防重与容灾**：所有源数据入库前进行 `hash` 校验防止重复，源站不可用时触发飞书/钉钉告警并使用上一日均价补齐。

### 2.3 数据清洗与标准化 (ETL)
建立 ODS (原始层) -> DWD (清洗明细层) -> DWS (汇总层) 的数据仓库架构。
*   **规格与单位对齐**：将不同数据源的“元/斤”、“元/吨”统一转换为“元/公斤”；将“统货”、“精品”、“通货”等非标规格映射至标准字典。
*   **异常值处理 (Outlier Detection)**：
    *   剔除负值、零值（非赠品情况）。
    *   基于 3-Sigma 法则或孤立森林 (Isolation Forest) 识别并平滑由于输入错误导致的“价格尖峰”。
*   **缺失值插补**：周末或节假日无报价时，采用线性插值 (Linear Interpolation) 或前向填充 (Forward Fill) 保证时序连续性。

## 3. 特征工程与数据建模基座 (Feature Engineering)

### 3.1 最小预测单元 (SPU_Tuple)
预测不再是宽泛的“苹果价格”，而是精确到四元组底座：**[产地] + [品种] + [规格] + [单位]**（例：山东烟台 + 富士苹果 + 80#以上一二级 + 元/公斤）。

### 3.2 特征构造体系
除历史价格时序外，构建多维特征以提升预测上限：
*   **时间/周期特征**：月份、星期几、是否法定节假日、是否处于传统农历节气（对农产品价格影响显著）。
*   **气象环境特征**：主产区近 30 天的降水量、极端天气预警次数（从公开气象 API 获取）。
*   **宏观与替代品特征**：CPI 农产品指数、强替代品（如猪肉与鸡肉）的同期价格变动率。

## 4. 分档多模型融合预测引擎 (Tiered Multi-Model Engine)

为了兼顾预测精度与不同数据丰富度，设计**动态分档路由**机制，而非单一模型。

### 4.1 模型分档策略
*   **Tier 1: 极小样本/冷启动 (历史数据 < 30天)**
    *   **算法**：规则基线 (Rule-based Baseline)、简单指数平滑 (SES)。
    *   **策略**：通过知识图谱“借用”相似产地或相似品种的历史趋势特征。
*   **Tier 2: 中等样本 (30天 <= 历史数据 < 半年)**
    *   **算法**：Prophet (Meta 开源，擅长处理节假日与季节性)、ARIMA、LightGBM。
*   **Tier 3: 大样本/复杂时序 (历史数据 >= 半年)**
    *   **算法**：LSTM / GRU (捕捉长距离时间依赖)、Informer (专为长时间序列设计的 Transformer 变体)。

### 4.2 动态融合与置信区间 (Ensemble & Confidence Interval)
*   **加权融合**：在验证集上计算各模型的 MAPE（平均绝对百分比误差），实际预测时采用 MAPE 倒数加权 (Inverse Error Weighting) 结合多个模型输出。
*   **概率预测**：不再仅输出绝对单点值（Point Forecast），而是通过分位数回归 (Quantile Regression) 或蒙特卡洛 Dropout，输出 80% 和 95% 的置信区间（Confidence Interval），为农户提供风险范围。

## 5. 高可用工程部署与服务化 (High Availability & Engineering)

### 5.1 架构分离与安全通信
*   **离线训练 (Python/GPU)**：每周定时触发（Airflow/Celery），拉取 DWS 层数据，重训 LSTM/Prophet 模型，并将最优权重文件保存至模型注册表。
*   **在线推理 (Python FastAPI)**：加载预训练模型，暴露 HTTP API。
*   **安全鉴权**：Node.js 后端与 Python 算法服务之间，采用 HMAC-SHA256 签名机制，防止内部接口被恶意调用。

### 5.2 优雅降级机制 (Fallback)
*   若 Python 模型服务宕机、超时（>2秒）或由于资源耗尽导致推理失败，Node.js 后端立刻捕获异常。
*   自动回退至 Node.js 内存中预置的轻量级算法（如简单移动平均 MA 或朴素预测 Naive Forecast），并在返回数据中标记 `fallback: true`，确保前端页面不白屏，业务永不中断。

## 6. 业务闭环与用户价值呈现 (Business Loop)

### 6.1 前端行情驾驶舱 (Frontend Visualization)
*   **ECharts/G2Plot 深度集成**：渲染历史真实曲线（实线） + 未来预测曲线（虚线） + 预测置信带（半透明阴影区域）。
*   **价格异动预警**：当预测未来 7 天内价格波动超过预设阈值（如涨跌幅 > 15%），UI 层高亮显示“暴涨/暴跌预警”标签。

### 6.2 智能大模型解读 (RAG Qualitative Report)
单纯的数据图表对部分农户理解门槛较高。
*   将模型预测结果（定量）与近期农业资讯库（定性）作为 Context，输入给 LLM (如 DeepSeek/GPT-4)。
*   生成接地气的白话文报告：“预计下周烟台富士苹果价格将小幅回落至 6.5元/公斤，主要受周边产区集中上市影响，建议已采摘农户尽早出库。”

## 7. 项目实施路径与里程碑 (Roadmap)

*   **Phase 1: 基础设施打通 (P0)**
    *   设计 MySQL 价格库表结构（SPU 粒度）。
    *   实现 Node.js 后端 `forecast-engine.js` 与前端图表的对接，移除所有的 `Math.random` 假数据，替换为基础算法打底。
*   **Phase 2: 数据底座建设 (P1)**
    *   接入全国农产品批发市场每日价格公开 API。
    *   完成数据清洗清洗脚本，沉淀历史 1 年的基础数据集。
*   **Phase 3: 深度学习模型上线 (P1)**
    *   Python 服务中引入 LSTM/Prophet 适配器。
    *   实现 Node.js 到 Python 服务的鉴权调用与降级策略。
*   **Phase 4: 业务闭环与大模型分析 (P2)**
    *   上线前端置信区间图表。
    *   集成 RAG 报告生成机制，实现完整的产品形态。
