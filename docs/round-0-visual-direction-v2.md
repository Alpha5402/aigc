# 第 0 轮视觉方向探索 v2：竞赛展示级 App 视觉方案

## 1. 上一版问题诊断

上一版 `docs/round-0-visual-direction.md` 是安全、可执行的基础规范，但确实不够“眼前一亮”。

1. 太像普通农业工具 App：核心判断是“暖色背景 + 绿色业务卡片 + 常规状态标签”，能用但缺少展示瞬间的强记忆。
2. 过于依赖常规 tokens：上一版把颜色、间距、圆角定义得较完整，但没有把它们转化为具体首屏画面。
3. 缺少首屏视觉冲击：没有定义 App 打开后第一眼看到什么、视觉中心在哪里、竞赛评委会记住哪一处。
4. 素材策略不够具体：只说“真实农田照片、作物特写”，没有给出关键词、裁切比例、放置页面、压缩和风格统一方法。
5. 缺少关键页面视觉原型描述：每个页面更多是结构建议，缺少“画面怎么长出来”的描述。
6. canvas 规划太保守：只列组件名和用途，没有说明具体绘制内容、位置、降级和动效边界。
7. 竞赛展示第一印象不足：上一版适合作为内部设计规范，不够像一个可被展示、讲述、截图传播的高完成度 App 方案。

v2 的目标是：保留农业真实感和业务边界，把 App 首屏做成“能被一眼记住”的智慧农业经营中枢。

## 2. v2 设计定位

**最终设计定位：会呼吸的农场经营中枢。**

它不是后台，不是普通农事记录工具，也不是 AI 聊天套壳。它应该像一个真实农场被压缩进手机：有田地、有作物、有天气、有风险、有行情、有销路，有明确的经营动作。

设计关键词：

- 真实田野，而不是抽象科技。
- 农场中控，而不是普通列表。
- 经营闭环，而不是单点功能。
- 局部动效，而不是炫技背景。
- 高质量照片 + 克制 canvas，而不是模板插画。

## 3. 三套更有冲击力的视觉方向

### 方案 A：沉浸式田野中控 Field Command

**一句话定位：把“我的地”做成一张会显示天气、作物、任务和行情的真实农场中控台。**

- 首屏第一眼画面：顶部 38%-45% 屏幕是一张明亮真实田野/果园横图，照片底部有柔和暗绿到透明遮罩；天气、位置、日期浮在图上，下面一组半悬浮经营指标卡压住图片边缘，继续向下是地块/作物横向卡。
- 核心色彩气质：深叶绿压标题，暖米白承接内容，晨光金做任务提醒，雾蓝只用于天气和数据说明。
- 关键素材风格：真实农田航拍、温室斜侧拍、果园晨光、作物近景；需要明亮、干净、无遮挡、适合竖屏裁切。
- 适合 canvas：照片下方叠加非常轻的田垄线、微风叶片轨迹、天气水滴/光照点，不持续大面积重绘。
- 重点改造页面：登录、我的地、添加作物、通知中心。
- 视觉记忆点：真实田野首图 + 悬浮经营指标 + 作物地块卡，第一眼就不像普通列表。
- 风险与控制：照片质量决定上限；必须选许可清晰的高质量素材，本地压缩。遮罩只服务文字可读，不做厚重滤镜。
- 为什么比上一版更有冲击力：上一版停留在卡片规范，这版把首屏变成真实农业场景和经营数据叠加的“农场驾驶舱”。

### 方案 B：地块雷达 Farm Plot Atlas

**一句话定位：用抽象地块地图建立“这是我的农场区域”的空间感，但不伪造真实地图。**

- 首屏第一眼画面：顶部是浅米色大画布，canvas 绘制不规则地块、田垄纹理和作物色块，地块上浮着作物名称、面积、健康状态；用户看到的不是列表，而是一张可管理的“农场图谱”。
- 核心色彩气质：米色画布、土褐线条、叶绿地块、丰收金高亮待办，整体像现代地图产品但不科技化。
- 关键素材风格：少用大图，更多使用轻量纹理、线性图标、局部作物缩略图。
- 适合 canvas：FarmPatternCanvas 作为首屏主体视觉，绘制田垄线、地块轮廓、轻微天气粒子；静态为主，局部轻动。
- 重点改造页面：我的地、销路匹配、行情品类导航。
- 视觉记忆点：作物卡片不再只是列表，而是地块浮层；“我的地”真的像“我的地”。
- 风险与控制：不能像游戏农场，也不能伪装真实地图；地块必须抽象、轻量，所有真实数据仍来自接口或列表计算。
- 为什么比上一版更有冲击力：上一版说“田垄纹理”，这版把地块空间感作为首屏主视觉，结构变化更明显。

### 方案 C：丰收闭环 Harvest Loop

**一句话定位：把种植管理、行情判断、销路匹配和营销生成串成一条“从田里到市场”的移动经营链路。**

- 首屏第一眼画面：上方是作物/农产品市场真实照片的局部裁切，中间是一条横向经营闭环：种植中、看行情、找买家、做营销；每个节点是一张可点击任务卡，底部进入具体作物和今日建议。
- 核心色彩气质：暖米白 + 深绿主线 + 果橙行动点 + 丰收金收益提示，颜色更有展示张力，但控制面积。
- 关键素材风格：果蔬装筐、田间采摘、农产品集市、合作社称重、运输装车；避免促销海报感。
- 适合 canvas：经营闭环路径、供需连接线、收益条微动、果实/麦穗极轻装饰。
- 重点改造页面：行情、销路匹配、营销助手、推荐详情。
- 视觉记忆点：App 不只是记录作物，而是清楚展示“种得好、卖得出、卖得明白”的闭环。
- 风险与控制：果橙和丰收金过多会促销化；收益表达必须是辅助经营，不做金融行情视觉。
- 为什么比上一版更有冲击力：上一版页面是并列模块，这版有一条可以被讲述的产品故事线，适合比赛展示。

## 4. 最终推荐方案

推荐采用 **方案 A：沉浸式田野中控 Field Command** 作为主方向，并吸收方案 B 的地块 canvas 空间感、方案 C 的经营闭环叙事。

最终成型应是：

- 登录页建立品牌第一印象。
- 我的地成为视觉样板页和 App 级首页。
- 行情、销路、营销围绕“经营闭环”延展。
- AI 问诊以“农技巡检工具”嵌入这个中控体系，不做聊天机器人。

选择理由：

- 最容易在竞赛展示中“一眼成立”：真实田野照片 + 经营指标悬浮 + 作物地块卡。
- 农业主题强，不靠泛科技符号。
- 与现有页面功能最兼容：我的地已经有天气、作物、概览、行情摘要和提醒，可以在不改接口的前提下升级画面。
- App、小程序、H5 都能降级：照片缺失时用 canvas 田垄背景，canvas 失败时用渐变色块和卡片。

## 5. 三个 App 首屏爆点方案

### 首屏爆点 1：真实农场驾驶舱

- 画面布局：顶部 320-380rpx 为真实田野/果园照片，照片底部叠加深绿柔和遮罩；其下 2x2 经营指标卡半悬浮覆盖图片边缘，再往下是“今日要看”的作物卡和近期提醒。
- 顶部区域：左上显示“早上好 / 今天的农场状态”，右上通知入口；天气、位置、日期用小型玻璃感不要过重，只做半透明暖白底。
- 卡片做法：指标卡采用白米色实卡，带 2rpx 柔边和低阴影；数字大、标签小，强调作物数量、总面积、待办、最近种植。
- 图片/canvas 位置：真实图作为顶部 hero；图片底部可叠 FarmPatternCanvas 的细线，形成田垄延伸感。
- 操作按钮：添加作物是右下浮动主按钮，或首屏指标区下方固定小 CTA；必须避让底部导航安全区。
- H5 适配：顶部 hero 改为 16:7 横向 banner，指标卡变 4 列，作物卡保持网格。
- 避免 AI 风格：不使用蓝紫光效、机器人、AI 字样装饰；“智能”通过天气、任务、行情关联体现。
- 为什么眼前一亮：第一眼是“真实农场 + 数据中控”，不是表单列表。

### 首屏爆点 2：地块地图式农场图谱

- 画面布局：首屏上半部分是一块抽象农场画布，3-5 个不规则地块块面错落排布；每块地上有作物名、面积和健康状态小标。下半部分是选中地块详情卡。
- 顶部区域：标题压在画布上方，右上角通知/定位；天气作为小悬浮标签，不遮挡地块。
- 卡片做法：地块浮层使用极浅白底，状态色边线；选中地块详情卡展示种植时间、健康度、下一步任务、行情摘要。
- 图片/canvas 位置：FarmPatternCanvas 是首屏主视觉；作物缩略图只在详情卡中小面积出现。
- 操作按钮：添加作物作为“新建地块档案”按钮，放在画布右下角但不覆盖地块文字。
- H5 适配：canvas 画布居左，右侧为选中地块详情；低性能或 canvas 失败时改为作物卡片网格。
- 避免 AI 风格：地块线条来自田垄和地图感，不使用网格、扫描线、发光点。
- 为什么眼前一亮：用户打开后看到的是“自己的农场区域”，空间感强，明显不是普通列表。

### 首屏爆点 3：丰收经营闭环

- 画面布局：顶部用作物装筐/采摘真实照片做局部视觉，照片下方是一条“种植管理 -> 行情判断 -> 销路匹配 -> 营销文案”的横向闭环卡带；下半屏展示今日重点作物和推荐动作。
- 顶部区域：主标题直接写“今天这批作物怎么管、怎么卖”，突出经营场景；天气和位置降为辅助。
- 卡片做法：闭环节点卡用不同语义色轻量区分，但主线仍是深绿；节点展示真实功能入口，不新增虚假功能。
- 图片/canvas 位置：照片占顶部 260-320rpx；HarvestDecorCanvas 只做节点连线和轻微麦穗线稿装饰。
- 操作按钮：主 CTA 根据上下文进入“添加作物”或“查看销路”，不能遮挡底部导航。
- H5 适配：闭环横向展开为四列工作台，适合竞赛演示“一页讲清业务闭环”。
- 避免 AI 风格：AI 不作为视觉主角，只作为营销/问诊工具能力嵌入节点。
- 为什么眼前一亮：第一屏就讲清项目价值，不只是“我有一些功能”。

### 首屏爆点 4：农技巡检联动

- 画面布局：顶部是作物叶片/田间巡检真实图，叠加“今日健康巡检”状态；中间是作物健康雷达条和风险提醒；底部给出“拍照问诊”“记录观察”“查看建议”三个操作。
- 顶部区域：少量红棕风险色只用于病害提醒，不做大面积警报。
- 卡片做法：建议卡按“观察、处理、复查”三段排布，结果可信。
- 图片/canvas 位置：AiAnalysisCanvas 用在分析态，不常驻首屏；首屏主要靠真实作物图和健康状态条。
- 操作按钮：拍照问诊是中心突出按钮，但仍在底部导航上方安全区内。
- H5 适配：作为我的地的右侧“巡检面板”或问诊页首屏。
- 避免 AI 风格：不出现机器人/聊天气泡主导页面，强调农技员式流程。
- 为什么眼前一亮：把“我的地”和“AI 问诊”打通，体现智慧农业价值。

## 6. 页面级视觉亮点规划

### 登录 / 注册页

- 视觉亮点：全屏真实农业场景背景，底部或中下部浮出品牌登录卡。背景建议用晨光果园、温室大棚通道、田间作物特写。
- 页面结构：顶部只保留品牌名和一句可信定位；表单卡不要过大，登录/注册切换清晰。
- 关键控制：不能像普通白底表单；不能使用版权不明背景；遮罩要自然，文字可读。

### 我的地

- 视觉亮点：首页级农场经营看板。顶部真实田野图或地块 canvas，叠加天气、位置、经营指标；作物卡像地块档案而不是列表项。
- 页面结构：Hero 农场状态 -> 经营概览 -> 作物地块卡 -> 选中作物档案 -> 近期经营提醒。
- 关键控制：保留作物列表、添加、查看、编辑、删除能力，不伪造健康度和任务。

### 添加作物

- 视觉亮点：“建立作物档案”的仪式感，而不是普通表单。顶部显示档案封面卡，下面是步骤式分组。
- 页面结构：档案封面 -> 基础信息 -> 地块/面积 -> 种植时间/上市计划 -> 备注 -> 底部保存。
- 关键控制：步骤感只组织输入，不拆断原字段和接口。

### AI 智能问诊

- 视觉亮点：农技证据区。上传图片不是普通按钮，而是“证据托盘”：图片、症状、作物名、时间一起组成问诊材料。
- 页面结构：问诊引导 -> 证据上传区 -> 分析进度 -> 结构化建议卡 -> 历史记录。
- 关键控制：不做 ChatGPT 式聊天主界面；不使用蓝紫科技光效。

### 行情页

- 视觉亮点：农业价格数据看板。首卡显示选中作物今日价格和趋势，旁边是短周期预测或附近市场摘要。
- 页面结构：关注作物 chips -> 今日价格主卡 -> 趋势图 -> 附近市场 -> 报告/建议。
- 关键控制：避免金融行情 App 的红绿大屏和密集 K 线；趋势图服务农产品经营判断。

### 销路匹配

- 视觉亮点：供需连接画面。顶部用 MatchPathCanvas 表达“我的待售作物 -> 多个商户”的连接，不伪造真实地图。
- 页面结构：待售产品 -> 匹配路径/销售建议 -> 收益对比 -> 商户推荐卡。
- 关键控制：匹配理由基于接口返回或可解释字段；联系、导航、感兴趣能力保留。

### 营销助手

- 视觉亮点：农产品销售素材工作台。产品图/作物档案在上，风格和卖点 chips 在中，结果卡在下。
- 页面结构：产品素材卡 -> 推广目标 -> 可信卖点 -> 生成结果 -> 复制/重写。
- 关键控制：不做廉价促销海报，不夸大认证/品质；AI 是生成能力，不是聊天主角。

### 通知中心

- 视觉亮点：分类消息中心。顶部显示未读摘要，下面用 tabs 分为经营提醒、行情预警、问诊结果、系统通知。
- 页面结构：消息概览 -> 分类 tabs -> 重点提醒卡 -> 时间线消息。
- 关键控制：未读状态清晰，但不堆叠高饱和红点。

### 运营轻后台

- 视觉亮点：品牌一致的轻后台。H5 下采用米白背景、深绿标题、紧凑 KPI、表格和表单双栏。
- 页面结构：运营概览 -> 模块 tabs -> 数据表格/审核表单/日志。
- 关键控制：不要强行花哨；权限判断、接口、审计逻辑不动。

## 7. Moodboard / 素材策略

### 推荐素材类型

- Hero 背景：真实农田、果园、温室通道、作物近景。
- 业务补充图：装筐农产品、采摘、称重、合作社市场、田间巡检。
- 纹理：田垄线、叶片纹理、浅色地形纹理、纸感米白底。
- 图标：线性图标，优先农业、天气、趋势、路线、电话、标签、相机、清单。

### 推荐搜索关键词

用于 Unsplash / Pexels / Wikimedia Commons / Openverse 等许可清晰平台，并逐项核对 license：

- `greenhouse vegetables natural light`
- `orchard morning light`
- `vegetable farm rows aerial`
- `rice field rows morning`
- `farmer inspecting crops`
- `fresh produce market crates`
- `tomatoes harvest crate`
- `leaf close up agriculture disease`
- `greenhouse aisle agriculture`
- `farm field texture rows`

中文辅助关键词：

- `温室 大棚 蔬菜 自然光`
- `果园 晨光 作物`
- `农田 田垄 航拍`
- `农户 田间 巡检`
- `农产品 市场 装筐`

### 图片裁切比例建议

- 登录页背景：9:16 竖图，建议输出 1080x1920 或 750x1334 压缩版本。
- 我的地 Hero：16:9 或 4:3 原图，移动端裁切为 750x420；保留中上部视觉主体。
- 行情/销路局部图：3:2 或 4:3，裁成卡片顶部 320x180。
- 营销助手产品图：1:1 或 4:3，适合产品素材卡。
- H5 管理端不使用大图，只使用小型品牌纹理或空状态插图。

### 页面素材分配

- 适合真实照片：登录/注册、我的地、营销助手产品卡、AI 问诊上传示例、销路匹配顶部局部。
- 适合线性图标：底部导航、状态标签、表单字段、通知分类、后台操作。
- 适合 canvas：我的地首屏、行情趋势、销路连接、问诊分析中、营销装饰。
- 不应该放大图：运营后台、通知列表正文、密集表单区、行情图表主区域。

### 统一素材风格

- 只选真实摄影，不混入 3D 卡通或 AI 插画。
- 光线统一为明亮自然光，不选强滤镜、夜景、蓝紫科技色。
- 人物出现时不露脸或不作为主视觉，避免肖像授权问题。
- 所有图片本地压缩：Hero 控制在 200-350KB，卡片图控制在 80-160KB。
- 每个素材进入 `src/static/images/...` 前必须先登记到 `ASSET_CREDITS.md`。

本轮不实际下载素材；第 1 轮如果需要素材，应先挑选 3-5 张候选图，确认 license，再本地化、压缩、登记。

## 8. Canvas 具体落地方案

### FarmPatternCanvas

- 绘制内容：浅土褐田垄曲线、不规则地块边界、少量叶绿地块填充、晨光方向的淡金色光带。
- 使用位置：我的地首屏 Hero 的底部叠层，或地块地图式首屏的主画布区域。
- 静态/动态：默认静态绘制一次；可选极轻微的光带位移，进入后台或页面隐藏即停止。
- 失败降级：显示 `linear-gradient(180deg, #f8f5ec, #eef6ea)` 加普通作物卡。
- 不遮挡点击：canvas 放在绝对定位背景层，层级低于内容，H5 可用 `pointer-events: none`，小程序端避免覆盖交互区域。

### TrendMiniChart

- 展示方式：行情作物卡右侧或底部绘制 7 日 sparkline；主行情页仍可复用 `PriceChart`。
- 无数据降级：显示“暂无趋势数据”和一条浅色占位线，不生成随机趋势。
- 视觉控制：线条用叶绿/雾蓝，涨跌状态只用小标签，不做金融红绿冲击。

### MatchPathCanvas

- 表达内容：左侧“我的待售作物”节点，右侧 3-5 个商户节点，中间用柔和曲线连接；线条粗细可表达接口返回的可成交数量或排序，但必须有文字解释。
- 使用位置：销路匹配页顶部推荐区或收益对比上方。
- 不伪造地图：不画真实道路、不画真实距离、不使用地图底图；只表达供需关系。
- 失败降级：用普通商户推荐卡 + “按预计净收益排序”文本。

### AiAnalysisCanvas

- 动效内容：围绕上传图片边缘做柔和扫描进度、叶脉式线条展开、三段式进度点：识别症状、整理原因、生成建议。
- 使用位置：AI 问诊发送后、结果返回前的分析卡内部。
- 避免 AI 风格：颜色只用叶绿、雾蓝、米白；不用蓝紫霓虹、粒子风、机器人、AI 大脑。
- 失败降级：显示 LoadingSkeleton 和步骤文案，诊断流程不受影响。

### HarvestDecorCanvas

- 绘制内容：营销助手结果卡背景的浅色果实轮廓、麦穗线稿、商品标签虚线，不承载正文。
- 使用位置：营销助手 Hero 卡或生成中状态卡。
- 避免促销风：不使用红黄爆炸贴、不使用大字号促销符号、不做电商大促色块。
- 失败降级：纯色 harvest soft 背景。

## 9. 第 1 轮“我的地”样板页验收标准

第 1 轮如果进入“我的地”样板页，必须达到以下标准才算合格：

1. 第一眼明显不是普通列表：首屏必须有 Hero、地块画布或真实农业图，不能从作物列表直接开始。
2. 有农场经营看板感：天气、位置、作物数量、总面积、待办/提醒等信息形成经营中控。
3. 有农业主题视觉记忆点：田野照片、田垄 canvas、地块卡至少落地一种。
4. 有高质量素材或 canvas 增强：不能只是绿色卡片；若素材未准备好，必须有可降级的 canvas/纹理方案。
5. 保留功能能力：作物列表、添加、查看、编辑、删除、行情摘要、通知跳转不得删除或弱化。
6. 没有 AI 模板风：不出现蓝紫霓虹、机器人、芯片、电路、AI 大脑、宇宙背景。
7. 没有土味农业站风：不使用廉价宣传图、夸张金色大字、促销海报式排版。
8. App 端优先：触控目标不低于 88rpx，底部导航避让清晰，滚动和浮动按钮不冲突。
9. H5 正常：宽屏不拉散，Hero 和卡片有合理最大宽度，后台入口不受影响。
10. 可作为其他页面视觉基准：颜色、卡片、按钮、状态、空/加载/错误态能迁移到行情、销路、问诊、营销。

## 10. v2 Design Decisions

- Anchor：自定义农业 App 方向，参考“高质量摄影 + 移动经营工具 + 地图/中控台信息组织”，不套用通用 SaaS 或 AI 产品视觉。
- Color palette：深叶绿、暖米白、土褐线条、丰收金、果橙行动点、雾蓝数据色。
- Typography：中文系统字体，标题加重，数字指标大字号；不引入花哨展示字体。
- Spacing：8rpx 基线，首屏允许更强纵向层次，卡片间距不堆满。
- Radius：Hero 和大卡 32-40rpx，普通卡 24rpx，按钮 20rpx，标签胶囊。
- Shadow：低饱和绿色阴影，突出悬浮经营卡，不做玻璃拟态堆叠。
- Motion：160-260ms 自然缓动，canvas 动效局部、可停、可降级。
