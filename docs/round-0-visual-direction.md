# 第 0 轮视觉方向探索与结构设计策略

## 1. 本轮目标与范围

项目是“云上农管家 / AgriCloudManager”，技术栈为 uni-app + Vue3 + SCSS，主要面向 App 端和小程序端，H5 作为辅助端。本轮目标是在正式改造业务页面前，确定一套自然、美观、专业、有记忆点、适合竞赛展示的智慧农业移动端视觉方向，并明确后续页面结构如何重设计。

本轮不修改业务页面、不修改接口、不修改路由、不改 Pinia/权限/管理端逻辑、不伪造关键业务数据。本轮交付为设计策略和规范文档，作为后续第 1 轮和第 2 轮落地依据。

## 2. 现状观察

- 项目已有 `src/styles/design-tokens.scss`、`src/styles/tokens.scss`、`src/styles/design.scss`，色彩方向已偏向暖米色背景、叶绿主色、丰收金、雾蓝数据色，适合继续深化。
- 公共组件已有 `AppCard`、`AppButton`、`StatusChip`、`AppHeader`、`AppPage`、`BottomNav`、`PriceChart`，后续不需要引入大型 UI 框架。
- 核心页面已覆盖登录/注册、通知、我的地、添加作物、行情、推荐详情、AI 问诊、销路匹配、感兴趣商户、营销助手和管理后台。
- “我的地”“AI 问诊”“销路匹配”“营销助手”已具备卡片化和工具流雏形；后续重点不是推翻，而是统一视觉语言、强化首屏记忆点、收束信息层级和状态表达。
- 资产目录目前以 logo、placeholder、tabbar 图标为主；未发现根目录 `ASSET_CREDITS.md`，后续若引入公开素材必须补齐。

## 3. 三套视觉方案对比

### 方案 A：晨雾田垄 Field OS

- 视觉关键词：晨雾、田垄、作物档案、轻量经营看板、可信农服。
- 色彩气质：暖米色大底、深叶绿主色、浅叶绿承接、土褐和丰收金少量点缀、雾蓝用于数据和 AI 分析。
- 页面氛围：像一个真实农场经营 App，清爽但不空，专业但不后台化。
- 适合页面：我的地、添加作物、AI 问诊、通知中心、App 底部导航。
- 图片/图标/插画风格：真实农田/作物局部照片优先，图标使用线性农业/经营类图标，避免卡通和 3D 混搭。
- canvas 可能性：轻量田垄纹理、地块边界线、天气/水滴/叶片点缀，一次性绘制为主。
- App 适配：强。首屏可以做沉浸式农场看板，适合 375-430px 手机宽度。
- 小程序/H5 适配：强。暖底和卡片结构对平台兼容友好。
- 风险：如果照片质量低或绿色过多，容易变普通农业工具；需要用留白、图表和层级解决。
- 模板感/土味/后台/促销风险：低。只要控制装饰密度，不使用夸张渐变和宣传图即可。

### 方案 B：丰收集市 Harvest Market

- 视觉关键词：丰收、交易、供需匹配、农产品上市、收益测算。
- 色彩气质：白米底、叶绿为主、果橙/麦金作为强提示色，价格涨跌用克制的金橙和松绿色。
- 页面氛围：更有销售和流通感，适合展示农产品从田间到商户的路径。
- 适合页面：行情、销路匹配、营销助手、感兴趣商户、推荐详情。
- 图片/图标/插画风格：农产品市场、果蔬特写、称重/装箱/运输场景；图标偏经营、电话、路线、标签、趋势。
- canvas 可能性：匹配度环形图、供需连接线、收益条形对比、价格 sparkline。
- App 适配：强。销售页可做成推荐卡和行动区，转化路径明确。
- 小程序/H5 适配：中高。信息密度较大，需要避免 H5 看起来像电商促销页。
- 风险：金橙使用过量会变促销页；收益指标太突出会接近金融行情 App。
- 模板感/土味/后台/促销风险：中。需要把“销售辅助”做成可信工具，而不是大促页面。

### 方案 C：农技巡检 Agronomy Lab

- 视觉关键词：问诊、观察、分析、风险提示、农技建议。
- 色彩气质：浅米灰/雾白底、叶绿为业务主线、雾蓝用于分析状态、红棕用于病害风险，整体偏冷静。
- 页面氛围：像农技员的移动巡检工具，强调流程、证据、建议和复查。
- 适合页面：AI 问诊、图片上传、病害结果页、通知风险、管理后台的运营监控。
- 图片/图标/插画风格：作物叶片、病斑局部、田间巡检照片；图标偏检查、相机、清单、风险、建议。
- canvas 可能性：上传分析进度、识别框柔和标记、风险分层条、处理建议流程线。
- App 适配：强。能避免 ChatGPT 套壳，把 AI 做成农技工具流。
- 小程序/H5 适配：中。若动效和分析态过多，小程序端需要降级。
- 风险：过于“实验室”会偏离农户日常使用；需要保留温暖农业气质。
- 模板感/土味/后台/促销风险：低到中。禁止使用机器人、AI 大脑、芯片和蓝紫科技视觉。

## 4. 最终推荐方案

推荐采用“晨雾田垄 Field OS”为主方向，并吸收“丰收集市”的销售表达和“农技巡检”的问诊流程表达。

选择理由：

- 最符合项目全局功能，不只服务单个页面。我的地、行情、销路、营销、问诊都可以统一在“田间经营系统”的产品叙事下。
- 与现有 token 基础一致，已有暖底、叶绿、丰收金、雾蓝方向，后续改造成本低。
- 农业感来自真实田垄、作物、经营数据和农技流程，不依赖 AI 模板化科技元素。
- 适合 App 和小程序首屏展示，能做出“眼前一亮”的农场经营看板，同时不牺牲长时间使用舒适度。
- H5 管理端可以延展为轻后台，不需要换成传统后台风。

最终设计定位：一个“田间经营驾驶舱 + 农技工具流 + 农产品销售助手”的移动端智慧农业 App。

落地规则：

- 新页面样式优先使用 `src/styles/tokens.scss` 和 `src/styles/design-tokens.scss`。
- 不再新增页面局部硬编码主色；确需新增颜色，先补 token，再在页面使用。
- `PriceChart` 的 renderjs 内仍有硬编码 `#52a355` 等颜色，下一轮可映射为当前主绿或通过 props 注入。
- 保留 uni-app 内置变量 `$uni-color-primary` 等，避免第三方组件失去主题。

## 7. 页面结构重设计策略

### 登录 / 注册

- 重构为品牌欢迎页 + 表单区，不做营销落地页。
- 首屏用暖色农田/作物纹理或本地合规照片，表单卡片保持清晰。
- 登录、注册、忘记/切换入口保留原路由和接口。

### 我的地 / 作物管理

- 定位为首页级“农场经营看板”。
- 首屏结构：天气/位置/日期状态条、经营概览、作物横向卡、当前作物档案。
- 作物列表改为卡片，不删除查看、编辑、删除、添加能力。
- 添加作物入口建议固定为右下浮动按钮或底部主 CTA，注意底部导航避让。

### 添加作物

- 从长表单改为分组表单：基础信息、种植信息、上市计划、补充备注。
- 移动端底部固定保存区，错误校验贴近字段展示。
- 图片/位置/日期等能力如原项目已有，不能弱化。

### AI 农技问诊

- 避免 ChatGPT 式通用聊天套壳，改为“症状描述 -> 图片上传 -> 分析状态 -> 建议卡片 -> 历史记录”的工具流。
- AI 结果以“可能原因、处理建议、观察复查、风险提醒”结构化展示。
- 上传中、压缩中、分析中必须有自然反馈，失败态明确可重试。

### 行情

- 重构为农业价格数据看板：关注作物 tabs、今日价格主卡、趋势图、附近市场、AI/RAG 报告。
- 数据图表克制使用雾蓝和叶绿，避免金融 App 风。
- 价格涨跌色只服务状态，不做大面积红绿刺激。

### 销路匹配

- 从商户列表升级为供需匹配页：待售产品、AI 销售建议、收益对比、匹配结果卡。
- 商户卡突出匹配理由、可成交数量、预计净收益、联系/导航/话术操作。
- 推荐理由必须基于接口返回或可解释计算，不伪造“智能评分”。

### 感兴趣商户

- 作为收藏/跟进清单，建议增加状态分组：待联系、已联系、可复谈。
- 保留原有商户查看、联系、移除或跳转能力。

### 营销助手

- 改为销售素材工作台：待推广产品、目标选择、可信卖点、生成结果、复制/重写操作。
- 明确“需要证明后使用”的卖点边界，避免生成夸大文案。
- 生成态可使用丰收感轻量装饰，但不能变促销大屏。

### 通知中心

- 从单列表改为分类消息中心：经营提醒、行情预警、问诊结果、系统通知。
- 未读态可用雾蓝/叶绿，不用高饱和红点堆叠。

### 运营轻后台

- H5/大屏宽度下使用轻后台结构：顶部概览、横向 tab、表格/表单双栏。
- 保持与 App 端同一色彩体系，但降低圆角和装饰密度，提高数据密度。
- 管理员权限判断、接口和审计相关逻辑不得改动。

## 8. 素材策略

本轮未下载或引入任何外部素材。

后续若使用公开资源，必须遵守：

- 只使用许可清晰的图片、图标、插画或纹理。
- 必须下载到本地 `src/static` 或明确的 assets 目录，不热链。
- 必须压缩到适合移动端加载的尺寸。
- 必须维护根目录 `ASSET_CREDITS.md`，记录文件名、来源平台、原始链接、license、用途、是否压缩/裁剪。
- 真实照片优先选择农田、温室、果园、菜地、作物特写、农产品市场、农户田间管理场景。
- 不使用版权不明素材、不使用带明显品牌识别的素材、不使用其他 App 截图、不混用真实照片/3D 插画/卡通图标。

素材气质：明亮、干净、自然、真实、有生命力、轻微科技感。

## 9. Canvas 使用策略

canvas 只能用于局部增强，不能替代表单、按钮、列表、正文、上传、路由和底部导航。

推荐组件规划：

- `FarmPatternCanvas`：我的地首屏田垄纹理、地块线条、作物生长背景。静态绘制一次，失败时显示纯色/渐变背景。
- `TrendMiniChart`：行情卡片 sparkline。优先复用现有 `PriceChart` 或 ECharts 能力，小图可 canvas。
- `MatchProgressCanvas`：销路匹配度环形图、供需连接示意。必须可用文本数字替代。
- `AiAnalysisCanvas`：问诊分析中柔和进度反馈。动画可关闭，页面离开停止。
- `HarvestDecorCanvas`：营销助手轻量丰收装饰。只做背景点缀，不承载文案结果。

技术规则：

- App、小程序、H5 均需降级方案。
- 避免浏览器专属 API，平台差异使用条件编译。
- 背景 canvas 使用 `pointer-events: none` 等方式避免遮挡交互，uni-app 端按平台能力处理。
- 静态纹理优先一次绘制，不持续重绘。
- 动画必须控制帧率，页面离开停止定时器或 requestAnimationFrame。

禁止 canvas 用于蓝紫霓虹粒子、赛博网格、AI 大脑、机器人、芯片电路、强发光光球或与农业无关的炫酷动效。

## 10. 明确禁止的视觉风格

- AI 模板风和 ChatGPT 套壳。
- 大面积蓝紫渐变、霓虹发光边框、赛博网格背景。
- 机器人、芯片、电路、AI 大脑、宇宙科技背景。
- 大量玻璃拟态。
- 通用 SaaS 后台、传统政府后台。
- 土味农业网站、廉价农产品促销页、外卖/电商大促风。
- 金融行情 App 风。
- 游戏化种田风。
- 与智慧农业无关的泛科技风。
- 版权不明、风格混乱、低清晰度、强 AI 生成感素材。

| 管理后台 | 轻后台 | KPI、表格、双栏表单、审计日志 | 不破坏权限 |

## 12. 后续落地原则

- 先统一全局 token 和公共组件，再逐页重构。
- 每次页面改造只改变展示和交互组织，不改变接口字段、路由、权限和状态管理。
- 所有空状态、加载态、错误态必须真实，不用假业务数据填充。
- 页面首屏要有明确主任务，不要堆叠说明性文案。
- App 和小程序优先检查触控尺寸、底部安全区、键盘顶起、图片上传和滚动。
- H5 端优先检查宽屏不拉散、管理端信息密度和表格可读性。
